# 吉他谱 → 离线跟弹播放器

本技能先把谱子逐小节转录成工程数据 `score.json`，再由脚本生成播放器。不直接手写 HTML 播放器，也不对谱面做自动识别。数据是唯一来源，修订时只改数据，再重新生成播放器。

## 五条原则

1. **为了方便使用，可以重新排版。** 播放器会按数据重画谱面，原谱也会按小节切开重排。
2. **尽量把全部内容排进一个版面，适应普通横屏显示器。** “原谱”页在宽屏上自动分栏、一屏放完。
3. **忠于使用者的内容。** 除排版外，未经使用者许可不得改动、删减或替换谱上的任何内容。有哪一部分你不做或做不了、会让成品和要求不一样，必须在动手之前说明并询问，不能做完再解释。
4. **未经使用者确认，不擅自对版权等法律事项作出认定。** 你自身有不能做的事，就当作你自己的限制如实说明，再和使用者一起找办法。
5. **反复思考是否穷尽了方法。** 遇到做不到的环节，不停在第一个替代方案上，不把工作量推给使用者。

## 文件

| 位置 | 用途 |
|---|---|
| `scripts/gsh.py` | 数据校验 `check`、播放顺序 `order`、生成播放器 `build`、音高互校 `pitchcheck`、裁图 `crop`、缩图 `shrink`。只用 Python 标准库；裁图和缩图调用 macOS 自带的 sips |
| `references/format.md` | score.json 的格式说明。动手转录前必须先读 |
| `references/transcription.md` | 识谱规则：指型图、六线谱、简谱怎么读，读不清时怎么处理。转录前必须先读 |
| `template/player.html` | 播放器模板，由 build 自动填入数据，不要手改 |
| `template/i18n.json` | 播放器九种界面语言的文字表，build 时嵌入 |
| `examples/selftest.score.json` | 自编测试谱，展示所有写法 |
| `tests/test_gsh.py` | 自动测试：`python3 tests/test_gsh.py` |

## 需要的环境

- Python 3（只用标准库）；能看图；能执行代码。没有代码执行能力的环境做不了，直接告诉使用者。
- `crop`、`shrink` 需要 macOS 的 sips。其他系统没有 sips 时，用当地已有的工具裁图、缩图，或请使用者提供已缩小的图片，并说明这一点。
- PDF 要先转成图片，每页一张。

## 开工前向使用者讲明

每次只问一个问题。谱上已经写明的不要问。

1. 识谱靠逐小节看图，不保证全对。每个小节都要使用者核对后才算确认。读不清的地方会列为疑点，不会凭猜测补上。
2. 谱子不会上传到任何第三方识谱服务，也不会交给外部模型处理。转录在本机完成。
3. 吉他技巧（滑音、击弦、勾弦、推弦等）只记录在数据里，不演奏；音色是合成的拨弦声。
4. 谱子较长时，先转录 4～8 个有代表性的小节给使用者核对。确认读法没有系统性错误后，再转录全曲。
5. 谱上没有标速度的，问使用者，或先按 80 做并在交付时说明。

## 流程

1. **准备**：在曲谱所在文件夹新建 `曲名_转录/`，原图不动。
   - `gsh.py shrink 原谱.png -o 原谱_4000.png`：生成供嵌入播放器的缩小图。
   - 多页谱：每页各缩一张，build 时按页序传入。
2. **看全貌**：读整页缩略图，确认以下内容，写进 `meta`、`tempo`、`key`、`capo`、`tuning`、`parts`：
   - 调号、拍号、速度、变调夹；
   - 声部数量；
   - 反复记号和跳转记号；
   - 段落名（前奏、主歌、副歌等），写进 `sections`。原谱没标的，按反复结构起名，不要自己定段落名；
   - 每行谱的小节分界。
3. **建指型表**：先读完所有和弦图，再开始读小节，规则见 `transcription.md` 第2节。
4. **逐行转录**：
   - 每行用 `gsh.py crop` 放大裁图，读 3～4 个小节；
   - 同时记下每小节在缩小图上的位置 `img.box`（按缩小图的像素计）；
   - 每读完一行，运行一次 `check`，有旋律声部的再运行 `pitchcheck`。`check` 列出的“大跳”逐条回原图核对八度点。
5. **疑点**：写进 `issues`，有关键疑点的小节标 `doubt`，其余标 `draft`。八度拿不准也是关键疑点。
6. **生成**：运行 `gsh.py build 曲名.score.json -i 原谱_4000.png -o 曲名.html`。
7. **自查**：在浏览器里打开生成的播放器，检查以下几项：
   - 重画谱面和原谱逐小节对得上；
   - “原谱”页的小节框位置准确；
   - 能正常播放，控制台没有报错。
8. **交使用者核对**：告诉使用者怎样逐小节对照，并列出全部疑点和假设。
   - 使用者确认后，把小节改为 `confirmed`、疑点改为 `resolved`，在 `edits` 里记下日期和确认人，然后重新生成。
   - 已确认的小节以后不得擅自改动。

## 成品具备的功能

- 重画谱面（六线谱、和弦图、简谱、歌词）与原谱对照页；两边都有当前小节高亮和随拍移动的竖线；原谱宽屏自动分栏、一屏放完。
- 伴奏、旋律各声部可静音、独奏、调音量；变速 0.5～1.5 倍；节拍器、预备拍；变调夹 0～7 品移调。
- 选段循环、段落按钮一键循环、点小节跳转、空格播放暂停、左右方向键换小节。
- 九种界面语言：简体中文、繁體中文、English、日本語、한국어、Español、Français、Deutsch、Português。疑点、假设等数据内容按转录时的语言显示。
- 歌词译文：使用者按句输入或整段粘贴译文，显示在谱面歌词下方，播放时顶部显示当前一句；可下载、从文件载入、清除。
- 疑点与状态页、旋律大跳提醒、工程数据导出。速度、音量、语言等设置记在本机浏览器里。

## 交付

- 给出 HTML 文件；平台支持发布网页的话，可同时发布成链接。发布为 Claude Artifact 时声明 `capabilities: {db:{}, user:{}, downloads:true}`，歌词译文才能“保存到账号”。
- 汇报时分清三种验证，没做到的照实写“未验证”：
  - **代码检查通过**：`check` 和 `pitchcheck` 无错误；
  - **浏览器操作已验证**：写明在哪个浏览器、做了哪些操作；
  - **听感已核对**：只有使用者本人试听后才能这样写。
- 列出全部未解决的疑点和按假设处理的地方。

## 修订已有工程

使用者指出错误时：

1. 先在 `issues` 或 `edits` 里记下使用者的原话；
2. 只改被指出的小节；
3. 运行 `check`，再重新 build；
4. 把改了哪些地方逐条告诉使用者。

## 已知限制（如实告诉使用者）

- D.S.、Coda 等跳转不会自动识别，要在 `playOrder` 里写明播放顺序。
- 速度变化只能在小节开头生效，渐快渐慢不演奏。
- 延长记号不演奏。
- 扫弦按固定的弦间间隔依次发声，不模拟力度和角度。
- 歌词乐句按休止自动划分，可能把两句并成一句；译文表格里会显示原词，对照着填即可。
