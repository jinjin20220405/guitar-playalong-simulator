# 吉他跟弹模拟器

把用户给的吉他谱图片，变成一个打开就能练琴的网页。思路是：**谱面不重画，直接用原图**（重画容易出错，用户也认得自己的谱），程序只负责三件事：知道每个小节在图上的位置、知道每个小节该发什么音、按节拍把两者对齐播放。

所以工作量集中在"转录"：把图上的六线谱和简谱读成数据。版面检测和页面生成都有现成脚本，不要重写。

## 成品长什么样

做完后，用户应当得到一个自包含的 HTML 文件（约 100–300 KB，不依赖网络），具备：

- 原谱按行切条，宽屏双栏一屏放完，窄屏单栏并自动滚到当前行
- 黄色竖线光标随拍子走，当前小节整格标黄，顶栏显示当前和弦、下一个和弦、小节号、第几遍
- 伴奏声（按六线谱逐音拨弦）与旋律声（按简谱）同步，各有静音按钮和音量条，节拍器同理
- 速度滑杆（默认取谱上标的拍速），播放中可改
- 变调夹下拉框（不夹到 5 品），伴奏和旋律整体升高相应半音，旁边显示实际调
- 段落一键循环（前奏、主歌、副歌……）与自选起止小节循环；"全曲"按反复记号和一、二房子走完整流程
- 点谱面任一小节跳转；空格播放或暂停，左右方向键换小节；可选预备拍
- 界面语言下拉框：简中、繁中、英、日、韩、西、法、德、葡九种，默认跟随浏览器语言；曲名、署名和谱面上的段落文字（前奏、主歌等）随语言切换
- “歌词译文”按钮：打开后歌词行出现虚线格，使用者自己填写当前语言的译文，存在本机浏览器，可用文本导出导入；没填的格子显示原歌词。录入面板里有保存到模拟器、下载到本地、从文件载入、清除本语言、清除全部几个按钮；还能整段粘贴译文（一行一句），页面按 `lyricPhrases` 标出的乐句位置自动分句入格
- 段落大意：`i18n` 里可给每个段落写一句概述（`gist`），播放到该段时显示在顶栏小节号后面
- 跟随系统深浅色

## 需要的环境

Python 3 + Pillow + numpy，能看图（读放大图转录），能执行代码。没有代码执行能力的环境做不了这件事，直接告诉用户。

## 流程

### 0. 先和用户确认两件事

每次只问一个问题，问完再做：

1. **用途**：跟弹（本技能默认）、指法演示、还是只练和弦？本技能只覆盖跟弹；用户要别的，说明后另行设计。
2. **发声**：只发伴奏、只发旋律、还是两者都发各带开关？默认两者都发。

其余按默认值做，在交付时说明即可，不要逐项盘问。同时提前告诉用户：图片分辨率低时个别音可能认错，做完需要他对照原谱校对。

### 1. 检测版面

~~~bash
python scripts/detect.py 谱.png --out work/
~~~

得到 `work/geometry.json`（小节坐标）、`work/report.txt`（每小节每个拍位上哪些弦有记号）、`work/zoom/`（放大图）。

看一眼脚本打印的结果是否合理：行数对不对、每行的小节线数量是否等于该行小节数加一、总小节数是否与谱上的小节号对得上。不对就调参数重跑（`--line-thr`、`--clef` 等，见脚本开头），或直接手改 `geometry.json`。

### 2. 转录成 song.json

这是最需要细心的一步。**先读 `references/song-schema.md`**，里面有数据格式、读谱规则和容易踩的坑；`examples/demo.song.json` 是一份格式样板（公有领域旋律，4 小节），格式照它写。

做法：

- 逐行查看 `work/zoom/sN.png`，读和弦名、简谱、反复记号、房子、段落标记
- 伴奏的弦位以 `report.txt` 为底稿（它比肉眼数线可靠），数字是几、十六分音符、连音线等细节看 `sNa.png`、`sNb.png`（4 倍放大）
- 记下谱面上每处段落文字（前奏、主歌、副歌、间奏、结尾、尾奏等）的位置，写进 `labels`；曲名和署名的各语种译法写进 `i18n`
- 用旋律反过来校验伴奏：前奏、间奏里吉他最高音通常就是简谱旋律，两边对不上说明有一边读错了
- `report.txt` 里标了"拍位数≠8"的小节必须逐个看放大图

没把握的音不要猜了就算，记下来，交付时列给用户。

### 3. 构建

~~~bash
python scripts/build.py --image 谱.png --geometry work/geometry.json --song work/song.json --out 曲名跟弹模拟器.html
~~~

脚本会先校验数据。"错误"要改到没有为止；"提示"（多为旋律时值超出一小节）逐条确认是不是有意的跨小节连音。

### 4. 自测

有无头浏览器就跑一遍 `python scripts/smoke_test.py 曲名跟弹模拟器.html`，它会播放几秒、切到循环、截两张图（宽屏和窄屏）并报告 JS 错误。看截图确认：光标落在正确的小节上、竖线大致压在音符上、双栏没有溢出。

没有无头浏览器就跳过，但要如实告诉用户"页面未经实际运行测试"。

无论哪种情况，**声音你听不到**，音色和音准只能由用户试听，交付时说清楚。

### 5. 交付

- 给出 HTML 文件；所在平台支持发布网页的话，同时发布成链接。发布为 Claude Artifact 时声明 `capabilities: {db:{}, user:{}, downloads:true}`，这样“保存到模拟器”和“下载到本地”两个按钮才可用；单独打开 HTML 文件时没有“保存到模拟器”，下载走浏览器自带的保存
- 用几句话说明怎么用（播放、调速、循环、跳转）
- 列出需要用户校对的地方：没把握的小节号、做过的简化（见下）、检测时手改过的地方
- 告诉用户：哪一小节听着不对，报小节号即可修改

## 默认的简化处理

这些是有意为之，交付时要告知用户：

- 倚音不弹
- 同音连线合并成一个长音；跨小节的连音把时值记在前一小节，后一小节开头补休止
- 滑音、击勾弦按普通音发声
- 扫弦、琶音记号按从低音弦到高音弦依次快速拨出处理
- 歌词不转录、不翻译，谱面上保留原文（歌词是受版权保护的完整作品）。页面带“歌词译文”录入功能：使用者自己在歌词行的格子里按小节填写所选语言的译文，页面在原位置盖上显示。你只负责在 `lyricRows` 里标出歌词行的位置、在 `lyricPhrases` 里标出每个乐句占哪几个小节，并可用自己的话为每个段落写一句大意（概述，不是逐句翻译）；不要代填、不要把歌词或译文写进任何文件
- 变调夹默认不夹，按谱面指型的实际音高（选调）发声；谱上标了原调的，可在 song.json 里用 `capo` 设默认品位，用户也能在页面上自选

## 常见问题

- **光标和音符错位**：该小节的 `x1`（第一个八分位的 x 坐标）或 `d`（八分位间距）不准。小节以休止开头时，检测到的"第一个记号"不是第一拍，要把 `x1` 改成小节线右侧约 16 像素处（参考同行其他小节的偏移）。
- **小节数对不上**：多半是小节线漏检或把符干当成了小节线，看 `geometry.json` 里每行的 `bars`，手工增删后同步修正 `measures`。
- **不是 4/4 拍**：在 song.json 里设 `beats`；模板按"每拍两个八分位"摆光标，6/8 这类复拍子可把一小节当 3 拍或按八分音符为一拍来记，并相应调整 `bpm`。
- **谱面有多页**：先把多张图上下拼成一张再检测。
- **不要改模板里的发声和调度逻辑**，除非用户明确要求换音色；那部分已经调好，改动容易引入节拍漂移。

## 文件清单

- `scripts/detect.py`：版面检测，输出坐标、弦位报告、放大图
- `scripts/build.py`：校验并生成 HTML
- `scripts/smoke_test.py`：无头浏览器冒烟测试（可选，需要 playwright）
- `assets/template.html`：页面模板（界面、合成音色、节拍调度都在里面）
- `references/song-schema.md`：song.json 格式与读谱规则，转录前必读
- `examples/demo.song.json`：song.json 的格式样板（公有领域旋律）
