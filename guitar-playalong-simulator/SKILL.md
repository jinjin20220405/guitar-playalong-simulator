# 吉他跟弹模拟器

把使用者给的吉他谱（图片或 PDF）变成一个打开就能练琴的网页：原谱显示在屏幕上，光标随拍子走，伴奏和旋律同步发声。

**做法是固定的七步，每一步都有现成脚本。照着做，不要自己另写程序，不要跳步，不要凭感觉改数字。** 每个脚本结束时都会打印"下一步"该运行什么。

## 五条原则

1. **为了方便使用，可以重新排版。** 多页、多栏的原谱会被自动拆开重排。
2. **尽量把全部内容排进一个版面，适应普通横屏显示器。** 页面会自动分栏，第 7 步会检查有没有滚动条。
3. **忠于使用者的内容。** 除排版外，未经使用者许可不得改动、删减或替换谱上的任何内容。有哪一部分你不做或做不了、会让成品和要求不一样，必须在动手之前说明并询问，不能做完再解释。
4. **未经使用者确认，不擅自对版权等法律事项作出认定。** 你自身有不能做的事，就当作你自己的限制如实说明，再和使用者一起找办法。
5. **反复思考是否穷尽了方法。** 遇到做不到的环节，不停在第一个替代方案上，不把工作量推给使用者。

## 需要的环境

Python 3、Pillow、numpy；能看图；能执行代码。处理 PDF 需要 `pdftoppm`（poppler-utils）或 PyMuPDF。第 7 步的自动核对需要 playwright，没有也能做，但要如实告诉使用者"页面未经实际运行测试"。没有代码执行能力的环境做不了这件事，直接告诉使用者。

## 开工前（只问必须问的）

每次只问一个问题。谱上已经写明的不要问。

- 谱上**没有标速度**：问使用者，或先按 80 做并在交付时说明。
- 你自己有不做的事（例如你不抄写歌词、不逐音转录旋律）：现在就告诉使用者。本技能的默认做法本来就不需要你做这两件事：旋律由网页自己识别，歌词译文由使用者自己填。

## 七步流程

下面的 `work/` 是工作目录，`scripts/` 是本技能的脚本目录。

### 第 1、2 步　转成图片、规整版面（全自动）

~~~bash
python scripts/prepare.py 曲谱文件 --out work/
~~~

曲谱文件可以是一张图片、一个 PDF，或按顺序列出的多张图片。脚本会：渲染 PDF、找出每页的六线谱、按栏拆开、按阅读顺序拼成单栏、统一缩放。

**看输出**：它会打印每页找到几个六线谱、几栏。数一下原谱，行数对不上就停下来告诉使用者（多半是图片太模糊或不是六线谱）。

### 第 3、5 步　定位、标位置（全自动）

~~~bash
python scripts/detect.py --out work/
~~~

它会生成：

- `work/report.txt`：小节编号表、需要人工核对的地方、主要拨弦型
- `work/zoom/s1.png`、`s2.png`……：每行谱的放大图，**每个小节上方用红字标了下标 [0] [1] [2]……**
- `work/zoom/pattern.png`：拨弦型的示例小节
- `work/song.txt`：下一步要填的表
- `work/geometry.json`：坐标（小节线、简谱行、歌词行的位置都在里面，不用手工量）

**必须做的核对**：打开 `report.txt` 看"需要人工核对"一节。

- 写着"（无）"：继续下一步。
- 提示某小节"很宽"：打开它说的那张放大图，看那一格里是一个小节还是两个小节（看简谱：一格里的拍数是不是两个小节的量）。是两个，就按提示在 `geometry.json` 该行的 `bars` 里补上它给的数字（保持从小到大）；是一个，就不管。
- 提示某小节"很窄"：同理，确认不是小节线就按提示删掉那个数字。
- 改过 `bars` 之后运行 `python scripts/detect.py --out work/ --keep-bars`，再看一遍。

### 第 4 步　读取谱面信息（这一步要你看图）

打开 `work/song.txt`，按里面的说明填。需要你看图的只有三样：

**(a) 和弦**。依次打开 `zoom/s1.png`、`s2.png`……，每张图从左到右，把每个小节上方的和弦名抄进 `chords:` 下对应的那一行，用空格分开。红字 [n] 是小节下标，一个 [n] 抄一个和弦。

- 这一小节上方没有和弦名（沿用前一个）：写 `-`
- 一小节里有两个和弦：写成 `F/E`
- 每行写的个数必须等于表里注明的小节数，下一步的脚本会检查

**(b) 拨弦型 `pattern`**。先让 pattern 留空，直接运行下一条命令，脚本会按检测结果给出一个建议，形如 `pattern: 0:B 0.75:3 1:1 1.5:2 1.75:3`。然后打开 `zoom/pattern.png` 核对：

- 音符下方只连**一条**横杠：八分音符，占 0.5 拍；连**两条**：十六分音符，占 0.25 拍；带附点的再多占一半
- 第一个音的拍位是 0，后一个音的拍位 = 前一个音的拍位 + 前一个音占的拍数
- `B` 表示低音弦（脚本会按和弦自动选第几弦），数字表示第几弦，1 是最细的那根
- 核对无误就把建议填进 `pattern:`；看不清就用建议值，并在交付时告诉使用者"伴奏节奏型是按位置推算的"

**(c) 其他几项**

- `title`：曲名。`credits`：演唱、编配、调，用 `|` 分开，照谱上写的抄
- `beats`：每小节几拍（看拍号上面的数字，2/4 填 2，4/4 填 4）。`key`：谱上"1=C"里的字母
- `bpm`：谱上标的速度；没标按"开工前"一节处理
- `pickup_rest`：第一个小节如果是弱起（前面空着、只有最后一两个音），填它开头空了几拍；否则填 0
- `sections`：谱上标了"前奏、主歌、副歌、间奏、尾奏"的，按红字下标写起止；没标可以不写
- `sequence`：有反复记号、房子、D.S. 的，按实际演奏顺序写成分段；**看不清就问使用者，不要猜**；没有反复保持默认
- `overrides`：个别小节明显和拨弦型不同时才写。整小节只有一个琶音或扫弦和弦写 `roll`；整小节不弹写 `rest`

填完运行：

~~~bash
python scripts/make_song.py --out work/
~~~

它会逐条指出填错的地方（哪一行、应该几个、你写了几个）。照着改，直到它说"第 4 步完成"。

### 第 6 步　切条嵌入（全自动）

~~~bash
python scripts/build.py --out work/ --html 曲名跟弹模拟器.html
~~~

"错误"要改到没有为止。

### 第 7 步　核对（全自动 + 看一眼截图）

~~~bash
python scripts/check.py 曲名跟弹模拟器.html
~~~

- 每一行都是 `[通过]` 才能交付。出现 `[不通过]` 就按它说的原因回到对应步骤。
- 打开它存下的截图看一眼：谱面完整、分栏整齐、黄色光标压在某个小节上。
- 记下"页面识谱"那一行的数字，交付时原样告诉使用者。

## 交付

- 给出 HTML 文件；平台支持发布网页的话同时发布成链接。发布为 Claude Artifact 时声明 `capabilities: {db:{}, user:{}, downloads:true}`。
- 如实报告，缺一不可：
  1. 页面识谱读出多少小节、多少小节拍数对不上（第 7 步的数字）
  2. 你在第 3 步补过或删过的小节线
  3. 你没把握的和弦、拨弦型、反复顺序、速度
  4. 声音你听不到，请使用者试听
- 告诉使用者：旋律认错的小节可以点页面上的“旋律校对”直接改；哪里不对报小节号。

## 成品具备的功能

原谱自动分栏、一屏放完；光标随拍走；伴奏、旋律、节拍器各带静音和音量；调速、预备拍、变调夹；分段循环、点小节跳转；九种界面语言；“旋律校对”；“歌词译文”（使用者自己填，可保存、下载、清除）。

## 出了问题怎么办

| 现象 | 做法 |
|---|---|
| 第 1 步说没有找到六线谱 | 图片太模糊，或不是带六线谱的吉他谱。告诉使用者，请他提供更清晰的文件 |
| 第 3 步小节总数和谱上的小节号对不上 | 看 report.txt 的小节编号表，找到小节数不对的那一行，打开那行的放大图，照"必须做的核对"补线或删线 |
| 第 4 步说某行和弦个数不对 | 回到那行的放大图，照红字下标一个一个重数 |
| 第 4 步说某个和弦不在内置表里 | 在 song.txt 末尾加一行 `shape 和弦名: 六位品位`（6 弦到 1 弦，x 表示不弹） |
| 第 7 步有滚动或超出屏幕 | 不要改模板。确认第 3 步的行数正确；仍不行就如实告诉使用者 |
| 第 7 步提示拍数对不上的小节偏多 | 多见于分辨率低的谱。如实告诉使用者，建议他提供更清晰的谱，或用“旋律校对”修正 |
| 旋律整体高了或低了八度 | 在 song.txt 里把 `key` 保持不变，告诉使用者；需要时由熟悉的人改 song.json 的 `tonicMidi`（加减 12） |

**不要改 `assets/template.html`**，除非使用者明确要求改界面或音色。

## 文件清单

- `scripts/prepare.py`：第 1、2 步
- `scripts/detect.py`：第 3、5 步
- `scripts/make_song.py`：第 4 步（song.txt → song.json）
- `scripts/build.py`：第 6 步
- `scripts/check.py`：第 7 步
- `assets/template.html`：页面模板
- `references/song-schema.md`：song.txt 与 song.json 的完整格式（一般不用看）
- `examples/`：样板
