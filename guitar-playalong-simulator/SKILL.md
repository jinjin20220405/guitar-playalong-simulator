# 吉他跟弹模拟器

把使用者给的吉他谱图片，变成一个打开就能练琴的网页。思路是：**谱面直接用使用者的原图**，程序只负责三件事：知道每个小节在图上的位置、知道每个小节该发什么音、按节拍把两者对齐播放。

版面检测、页面生成、页面内的简谱识别都有现成脚本和模板，不要重写。

## 五条原则

做这件事的全过程都按这五条来，后面的流程只是它们的展开。

1. **为了方便使用，可以重新排版。** 原图是竖版、多栏、多页都没关系，按行切开后由页面重新分栏。
2. **尽量把全部内容排进一个版面，适应普通横屏显示器。** 模板会在 1 到 4 栏里自动挑能把谱面放得最大的栏数，宽屏下不滚动、不翻页。使用者提出"一屏放完"时，这是硬性要求，交付前要实测。
3. **忠于使用者的内容。** 谱上的音符、和弦、歌词、标记、顺序，都照使用者给的来。除了为方便使用而做的排版调整，未经使用者许可不得改动、删减或替换任何内容。要求里有哪一部分你不做或做不了、会让成品和要求不一样，必须在动手之前说明并询问，由使用者决定，不能做完了再解释。
4. **未经使用者确认，不擅自对版权等法律事项作出认定。** 使用者的材料是否受保护、使用是否合法，不是你来下结论的事，也不要以此为由替使用者改要求。如果你自身有不能做的事（例如你所在的平台不允许你逐字抄写或逐音转录某些内容），就如实说"这一步我不做"，把它当作你自己的限制来讲，然后和使用者一起找别的办法。
5. **反复思考是否穷尽了方法。** 目标是让人方便地达成目的。遇到做不到或不让做的环节，不要停在第一个想到的替代方案上，尤其不要把工作量推给使用者。先问自己：能不能让页面自己完成、能不能导入现成文件、能不能换一种呈现方式。把想到的办法列给使用者选。

## 成品长什么样

一个自包含的 HTML 文件（不依赖网络），具备：

- 原谱按行切条，自动分栏，宽屏一屏放完；窄屏（手机竖屏）单栏并自动滚到当前行
- 黄色竖线光标随拍子走，当前小节整格标黄，顶栏显示当前和弦、下一个和弦、小节号、第几遍
- 伴奏声按六线谱的拨弦型发出；旋律声由页面在使用者的浏览器里**自动读简谱**生成；伴奏、旋律、节拍器各有静音按钮和音量条
- “旋律校对”按钮：拍数对不上的小节标红框，点格子可改，清空恢复自动识别
- 速度滑杆、预备拍、变调夹（不夹到 5 品）
- 段落一键循环与自选小节循环；"全曲"按反复记号和房子走完整流程；点任一小节跳转
- 九种界面语言；曲名、署名和谱面上的段落文字随语言切换；段落大意（可选）
- “歌词译文”按钮：使用者逐格填写或整段粘贴译文，可保存、下载、载入、清除

## 需要的环境

Python 3 + Pillow + numpy，能看图，能执行代码。没有代码执行能力的环境做不了这件事，直接告诉使用者。

## 流程

### 0. 动手前的沟通

每次只问一个问题。必须先弄清的只有两件事，其余按默认做并在交付时说明：

1. **用途**：跟弹（本技能默认）、指法演示、还是只练和弦？
2. **发声**：只发伴奏、只发旋律、还是两者都发？默认两者都发。

同时在这一步把你自己的限制讲清楚（原则 3、4）：如果有哪一部分你不会去做，现在就说，并给出替代办法让使用者选。

### 1. 准备图片

`detect.py` 按"单栏、谱线间距约 9 像素"设计。原图不符合时先处理：

- **多栏或多页**：把各栏、各页按阅读顺序上下拼成一张单栏长图再检测。成品的分栏由页面自己决定，不受原图栏数影响。
- **分辨率很高**（谱线间距远大于 9 像素）：缩到谱线间距约 9 像素的一张用于检测，另留一张 2 倍大小的用于显示和页面识谱，`geometry.json` 的坐标同比放大。
- **分辨率很低**：照常做，但提前告诉使用者页面识谱的准确率会下降。

### 2. 检测版面

~~~bash
python scripts/detect.py 谱.png --out work/
~~~

得到 `work/geometry.json`（小节坐标）、`work/report.txt`（每拍位上哪些弦有记号）、`work/zoom/`（放大图）。核对行数、每行小节线数、总小节数。不对就调参数重跑，或手改 `geometry.json`。谱线很粗、记号压线的谱，`report.txt` 的弦位可能不可靠，以放大图为准。

### 3. 准备 song.json

**先读 `references/song-schema.md`**。需要填的内容：

- **和弦**：逐小节读和弦名
- **伴奏**：按六线谱的拨弦型填 `acc`。先放大看符杠确定节奏型（哪几个音、各占多长），多数歌曲的唱段是同一个型反复，确认后逐小节套用，个别不同的小节单独写
- **旋律**：默认不手写，在 `jianpuRows` 里标出每行谱简谱所在的纵向位置，页面打开时自己识别。使用者明确要求由你逐音转录、而你也可以做时，才填 `mel`
- **位置信息**：段落文字 `labels`、歌词行 `lyricRows`、乐句 `lyricPhrases`，都只记位置
- **演奏顺序**：反复记号、房子、D.S. 等写进 `sequence`；谱上看不清就问使用者，不要自己猜一个顺序
- **速度**：谱上没标就问使用者，或先按常见速度做并在交付时说明

没把握的地方记下来，交付时列给使用者。

### 4. 构建

~~~bash
python scripts/build.py --image 谱.png --geometry work/geometry.json --song work/song.json --out 曲名跟弹模拟器.html
~~~

"错误"要改到没有为止；"提示"逐条确认。

### 5. 自测

有无头浏览器就跑 `python scripts/smoke_test.py 曲名跟弹模拟器.html`，并额外确认：

- 宽屏下没有滚动条，全部谱行都在一屏内（原则 2）
- 页面识谱的结果：认出多少小节、多少小节拍数对不上（页面“旋律校对”面板里有这个数字）
- 光标落在正确的小节上

没有无头浏览器就如实说"页面未经实际运行测试"。声音你听不到，音色、音准、节奏型都要使用者试听。

### 6. 交付

- 给出 HTML 文件；平台支持发布网页的话同时发布成链接。发布为 Claude Artifact 时声明 `capabilities: {db:{}, user:{}, downloads:true}`，“保存到模拟器”和“下载到本地”才可用
- 说明怎么用
- 如实报告：页面识谱的准确率、没把握的小节、你做过的推定、和使用者要求不一致的地方
- 告诉使用者：哪一小节不对，报小节号即可修改

## 默认处理

以下是为了能做出来而采取的默认做法，交付时告知使用者；使用者有不同要求的，按使用者的来：

- 倚音不弹；滑音、击勾弦按普通音发声
- 页面识谱不处理连音线（会重新发音）
- 页面识谱遇到拍数对不上的小节，按比例压缩或拉伸到一小节播放，并标红
- 扫弦、琶音记号按从低音弦到高音弦依次快速拨出
- 变调夹默认不夹，按谱面指型的实际音高发声；可用 `capo` 设默认品位

## 常见问题

- **光标和音符错位**：该小节的 `x1`（第一个音的 x 坐标）或 `d`（八分位间距）不准。可取本小节第一个音的实际位置作 `x1`，`d` 取"到右小节线的距离 ÷ 每小节八分位数"。
- **小节数对不上**：小节线漏检或把符干当成了小节线，手改 `geometry.json` 里该行的 `bars` 并同步 `measures`。
- **页面识谱错得多**：先检查 `jianpuRows` 的范围：上边要包住连音弧线和高音点，下边要包住下划线和低音点；下面有歌词时，下边切在第一行歌词的中间。
- **不是 4/4 拍**：设 `beats`。模板按"每拍两个八分位"摆光标。
- **不要改模板里的发声和调度逻辑**，除非使用者明确要求；改动容易引入节拍漂移。

## 文件清单

- `scripts/detect.py`：版面检测
- `scripts/build.py`：校验并生成 HTML
- `scripts/smoke_test.py`：无头浏览器冒烟测试（可选）
- `assets/template.html`：页面模板（界面、分栏、合成音色、节拍调度、简谱识别、多语言）
- `references/song-schema.md`：song.json 格式与读谱规则
- `examples/`：数据样板
